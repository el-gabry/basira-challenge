# Official Competition Source Foundation

## Core rule

The competition runtime does not inherit religious-source
eligibility from the imported Basira baseline.

A source must pass the competition admission pipeline before
it may support an answer.

## Admission pipeline

Official scientific reference
→ source identity
→ source eligibility
→ exact artifact identity
→ version / edition metadata
→ cryptographic hash
→ structural audit
→ optional cross-source attestation
→ runtime admission

## Source presence is not source trust

These are separate facts:

1. a dataset exists;
2. Basira can parse it;
3. its claimed identity is verified;
4. the competition scientific reference permits its use;
5. the exact artifact is governed;
6. the artifact may support an answer.

Only step 6 grants runtime answer eligibility.

## Legacy baseline

Existing Basira manifests, adapters and evaluation artifacts are
preserved as prior R&D.

Their previous eligibility does not automatically transfer to the
competition runtime.

An old adapter may be reused as engineering infrastructure if the
new competition artifact passes this admission process.

## Quran

Quran witnesses require explicit identity metadata before
cross-source comparison:

- source;
- edition/release;
- riwaya;
- rawi where applicable;
- rasm standard;
- dabt standard;
- verse/reference identity;
- artifact hash.

A valid riwaya, rasm or dabt difference must never be classified
as textual corruption merely because strings differ.

## Shamela

Shamela is treated as a corpus container.

Eligibility is decided per governed book/artifact, not for the
entire container.
